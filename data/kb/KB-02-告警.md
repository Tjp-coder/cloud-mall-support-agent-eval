# KB-02 告警模块

> 模块:告警(AL)| 条目区间:AL-101~AL-135 | 状态:v0 初稿,待核对与评审
> 来源口径:基于在职期间的业务理解自行整理编写的模拟文档,数值为自洽设计。

---

## 1. 对象定义

- **告警规则**:用户为单个资源的单个指标配置的触发条件(阈值、连续周期、通知渠道),规则编号格式 `ALR202608160001`(ALR+年月日+4 位序号)。
- **监控指标**:平台采集的资源性能数据,分计算/存储类与网络类,用于告警判断与图表展示。
- **通知渠道**:平台发送告警通知的渠道,支持邮件与短信两种。
- **告警记录**:告警触发产生的历史记录,记录编号格式 `ALH202608160001`(ALH+年月日+4 位序号)。
- **示例对象**(供用例引用):规则 `ALR202608160001`(虚拟机 CPU 使用率阈值 90%)、告警记录 `ALH202608160001`、用户 138****8888(企业"XX 科技有限公司")。

---

## 2. 规则条目

### 2.1 监控与指标

- AL-101 监控范围:告警监控覆盖虚拟机、容器、公网IP 三类资源。
- AL-102 计算/存储指标:虚拟机与容器监控 CPU 使用率、内存使用率、磁盘读写速度三项指标。
- AL-103 网络指标:公网IP 监控公网入流量、公网出流量、出包量三项指标。
- AL-104 采集频率:指标数据默认每 1 分钟采集一次,采集频率由平台统一配置。
- AL-105 指标单位:CPU/内存使用率单位为 %;磁盘读写速度单位为 MB/s;公网入/出流量单位为 Mbps;出包量单位为 包/秒。
- AL-106 阈值方向:指标值达到或超过配置阈值时触发告警(即值 ≥ 阈值)。
- AL-107 监控图表:监控指标可在控制台以图表查看实时与历史数据。

### 2.2 规则配置

- AL-108 规则粒度:一条告警规则绑定单个资源的单个指标,不同资源或不同指标需分别创建规则。
- AL-109 多规则:同一资源可创建多条告警规则,分别监控不同指标或同一指标的不同阈值。
- AL-110 阈值配置:CPU/内存使用率默认阈值 90%,可自定义;磁盘读写速度、公网入/出流量、出包量阈值由用户按需填写。
- AL-111 连续周期:指标连续 N 次采集均达到阈值才触发告警,N 默认 3,可配范围 1~10。
- AL-112 中间未达标:连续周期计数中任一次采集未达标,计数清零并重新计数,本次不触发告警。
- AL-113 恢复后重置:告警触发后指标恢复正常,计数清零;再次触发需重新连续 N 次达标。
- AL-114 规则启停:告警规则支持启用/禁用,禁用后不再进行指标判断,也不发送通知。
- AL-115 规则编辑:规则可修改阈值、连续周期、通知渠道,保存后立即生效。
- AL-116 规则删除:规则删除后停止监控对应指标,已产生的历史告警记录仍保留。

### 2.3 状态与通知

- AL-117 通知渠道:通知支持邮件与短信两种渠道,每条规则至少配置 1 种渠道。
- AL-118 告警通知:连续 N 次达标触发告警时,向规则配置的渠道发送告警通知。
- AL-119 恢复通知:告警恢复为正常时,发送恢复正常通知。
- AL-120 数据不足通知:状态切换为数据不足时,单独发送 1 次通知。
- AL-121 通知去重:告警持续期间,同一规则的通知去重间隔为 30 分钟,30 分钟内最多发送 1 次。
- AL-122 通知内容:告警通知包含资源名称、指标名称、当前值、阈值、触发时间。
- AL-123 接收人:通知发送至规则配置的手机号与邮箱。

### 2.4 历史与查询

- AL-124 告警记录:每次告警触发生成 1 条告警记录,含资源、指标、触发时间、触发值、状态。
- AL-125 历史保留:历史告警记录保留 90 天,超过 90 天自动清理。
- AL-126 监控数据保留:监控图表数据保留 30 天,超过 30 天自动清理。
- AL-127 查询方式:历史告警可按资源、指标、时间范围、状态筛选查询。
- AL-128 记录状态:告警恢复正常后,对应告警记录的状态更新为已恢复。

### 2.5 异常与容错

- AL-129 通知失败:通知发送失败(如邮箱密码过期、短信模板未配置)时,系统记录失败原因,配置修复后恢复发送,失败期间不自动补发。
- AL-130 阈值校验:阈值必须为正数,CPU/内存阈值有效范围 1~100%;非法值或为空无法保存规则。
- AL-131 连续周期校验:连续周期 N 必须为正整数,非法值无法保存规则(可配范围见 AL-111)。

### 2.6 告警等级与策略(原型核对追加)

- AL-132 告警等级:告警分 高/中/低 三级;等级由用户创建规则时选择,影响通知内容与展示优先级。
- AL-133 统计周期:阈值判断按统计周期聚合,默认统计周期 180 秒(3 分钟),周期时长可配置。
- AL-134 告警策略:支持"在 X 分钟内累计触发 N 次则告警 1 次"与"每 X 分钟告警一次"两种频率策略,用于控制告警通知的发送频次。
- AL-135 阈值条件:阈值比较支持 大于/小于 两种方向(见 AL-106),聚合方式支持 平均值/最大值/最小值 三种,如"连续 2 个 180 秒周期内 CPU 使用率平均值大于 5% 时告警"。

## 3. 状态机

```
数据不足 → 恢复正常 → 告警
   ↑          │        │
   └──────────┴────────┘
   (恢复正常或告警状态下,资源关机/删除/数据中断时回到数据不足)
```

- **数据不足**:资源关机、删除或采集链路中断时进入,无监控数据,不做告警判断;数据恢复采集后,指标低于阈值进入恢复正常,指标达到阈值则开始连续周期累计。
- **恢复正常**:指标值低于阈值;连续 N 次采集均达标后进入告警,期间任一次未达标计数清零、仍为恢复正常。
- **告警**:连续 N 次达标触发,通知已发送;指标回落至阈值以下后进入恢复正常。
- **回到数据不足**:恢复正常与告警状态下,资源关机、删除或数据中断均回到数据不足,并单独发送 1 次通知(见 AL-120)。

## 4. 边界与拒答

**能答:** 监控范围与指标、采集频率、阈值配置、连续周期边界、通知渠道与去重、历史告警查询、数据不足与恢复规则。

**不能答(拒答依据):**
- 操作类:帮我创建/修改/删除告警规则、调整阈值 → 客服只提供咨询,不执行任何操作。
- 内部类:监控采集的底层实现、通知网关架构、资源成本构成 → 不对外披露。
- 他域类:容器/虚拟机的购买与生命周期、开票/返佣/算力券问题 → 引导至对应模块(联动见第 5 节)。

**需澄清(模糊问题的土壤):**
- "我的告警"但用户有多个资源/规则 → 要求提供资源名称或规则编号。
- 阈值/周期数值不清 → 要求明确具体指标与数值。
- "为什么没收到通知" → 要求确认资源、触发时间与通知渠道。

---

## 5. 联动规则

- **资源关机/删除 → 数据不足**:容器或虚拟机关机、删除后,该资源监控指标进入数据不足,并单独发送 1 次数据不足通知(见第 3 节状态机)。
- **监控图表 ↔ 告警**:监控图表标注告警阈值线,告警触发时间点与告警记录时间一致。
- **通知 → 环境配置**:通知依赖邮件/短信服务,邮箱密码过期或短信模板未配置会导致通知漏发(见 AL-129)。
