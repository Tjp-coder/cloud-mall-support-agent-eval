### Q3：context_recall 为什么需要 golden_contexts？你标了多少？

- [ ] 检索类 golden_contexts 非空：`____ / 40`
- [ ] 人工评审轮数：`____` 轮
- [ ] 评审修正的问题数：`____` 个

**达标线：**
60/60 字段完整；检索类 40/40 非空；有评审记录。

### Q4：裁判模型可信度怎么验证？

**面试原题变形：**
“LLM-as-judge 可靠吗？”“裁判模型自己打错了怎么办？”“你怎么校准？”

**90 秒答题框架：**
> “我抽 30 条测试集做人工标注，再用裁判模型按同一 rubric 打分，算一致率和 Cohen's kappa。不达标就调裁判 prompt 重跑一轮。然后分析分歧 case，看裁判是偏严还是偏松，最后定阈值。框架给的分数我默认不直接信，先校准再用。”

**必填数字：**
- [ ] 人工校准样本：`____ / 30`
- [ ] 人机一致率：`____%`（参考 ≥85%）
- [ ] Cohen's kappa：`____`（参考 ≥0.6）
- [ ] 分歧 case 数：`____`，其中裁判偏严 `____` 条、偏松 `____` 条
- [ ] 裁判 prompt 调优轮次：`____` 轮
- [ ] 最终采用的评分阈值：`____`

**达标线：**
30/30 完成；一致率/kappa 记录真实值；未达参考值时照实写分歧分析（裁判 prompt 最多调 1 轮），有结论即完成。

### Q6：调优改了什么，指标怎么变？

**面试原题变形：**
“你怎么证明这个改动是有效的？”“chunk 从多少改成多少，为什么？”

**90 秒答题框架：**
> “控制变量，一次只改一个。检索层做了 chunk_size/overlap/top-k 对比，生成层改了拒答和引用 prompt。同一份冻结测试集跑 RAGAS，看前后 delta。最后结论落到具体数字：改了什么，哪个指标涨了，哪个没变。”

**必填数字：**
- [ ] 检索层实验配置数：`____` 个（记录每个的 chunk_size / overlap / top_k）
- [ ] 生成层 prompt 实验数：`____` 个
- [ ] 最终选用的检索配置：chunk_size=`____`，overlap=`____`，top_k=`____`
- [ ] 调优后变化最大指标：`____`，delta：`____`
- [ ] 是否有指标下降超过 0.05：`是 / 否`

**达标线：**
≥1 组检索实验 + ≥1 组 prompt 实验；前后对比表完整；能一句话说出归因。

### Q7：p95 延迟和 token 成本是多少？

**面试原题变形：**
“token 成本怎么算？”“单轮问答多贵？”“延迟多少？”

**90 秒答题框架：**
> “每次评测调用都埋了延迟和 token 数，所以 p50/p95/TTFT 和成本是评测框架的副产品。单轮成本 = input token 单价 × 平均输入 + output token 单价 × 平均输出。并发压测是另一件事，我这次没把大规模并发作为核心指标。”

**必填数字：**
- [ ] 延迟统计样本量：`N = ____`
- [ ] p50 延迟：`____ ms`
- [ ] p95 延迟：`____ ms`
- [ ] TTFT（首 token 时间）：`____ ms`
- [ ] 平均输入 token：`____`，平均输出 token：`____`
- [ ] 单轮平均成本：`____ 元`（附价格公式）
- [ ] 是否做 Locust 并发压测：`做了 / 没做，原因：____`

**达标线：**
p50/p95/TTFT、token、单轮成本全部有真实样本量；**这是核心埋点，不可裁剪**。可裁剪的是 Locust 并发压测，不是这一题的数据。
