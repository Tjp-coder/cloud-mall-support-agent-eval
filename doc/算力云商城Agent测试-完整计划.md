## 1. 核心指标与参考基线（基线对比用，不是及格线）

| 层 | 指标 | 参考值 |
|---|---|---|
| 检索 | context_precision / context_recall / Recall@5 | precision ≥0.85，recall ≥0.80，Recall@5 ≥0.90 |
| 生成 | faithfulness / answer_relevancy | faithfulness ≥0.90，relevancy ≥0.80 |
| 行为 | 拒答精确率 / 澄清准确率 | 拒答精确率 ≥0.95 |
| 工具 | 工具选择准确率 / 参数 F1 / 多步成功率 | ≥0.95 / ≥0.95 / ≥0.90 |
| 裁判 | 人机一致率 / Cohen's kappa | ≥85% / ≥0.6 |
| 安全 | 7 条对抗 case 攻击成功率 | **= 0/7** |
| 延迟成本 | p50 / p95 / TTFT / 单轮 token 成本 | 出真实基线，不硬设指标 |
| 并发 | Locust 并发压测 | **可选，不做硬指标** |

**参考值使用规则（提前定死，防止 D7–D8 分数焦虑演变成范围膨胀）：**
1. 上表数值是**基线对比参考值**，不是及格线。实测未达标 = 一个数据点，不是失败。
2. 未达标的标准动作：**记录原因 + 归因分析 + 写进调优报告作面试素材**，该项即视为完成；严禁为凑分反复调参消耗工期。
3. 调优实验轮数封顶：检索 5 组（D7）+ prompt 2 组（D8），跑完即止，不因“分数不好看”追加实验。
4. 面试可用素材示例：“faithfulness 基线 0.72，加 query rewrite 后到 0.85，还没到 0.9 参考线，分析原因是 XX”——比硬凑到 0.9 更真实、更能体现分析能力。
5. 例外：安全对抗攻击成功率 **=0/7** 是硬基线——攻击成功属于必须修复的缺陷，修复后复验至 0/7，不属于“记录原因即完成”。

## 5. 裁剪规则（时间不够时按序执行）

| 顺序 | 项目 | 影响 |
|---|---|---|
| 1 | Streaming | 面试说“场景不需要，未做” |
| 2 | Locust 并发压测 | 保留 p95/token 成本，诚实说“没做并发” |

| 4 | 多轮上下文 | 面试说“场景单轮为主，未做” |
| 5 | 一致性测试 | 面试说“了解方法，未做” |
| 6 | D12 上午 schema | 尽量不砍，砍了影响工具参数可信度 |

**不可砍清单：** 测试集冻结、RAGAS 基线+调优对比、裁判校准、工具多步、异常容错、安全对抗、延迟/token 埋点、缺陷单、总报告、10 题自检。

### 5.1 范围治理铁律（本版定稿新增，长期有效）
1. 任何新增测试维度：先写进第 2.2 节可裁剪清单并**标注预计半天成本**，观察一天后再决定是否入主线；不口头加塞、不当日加塞。
2. 本计划已定稿：范围已历经 MVP → 接近生产 → AI 概念全覆盖 → mock 测试图谱 → 本版 共五轮扩展，**不再对比第 6 个方案**，新想法一律进 backlog。
3. 每天收工必须在变更记录写一行（做了什么、砍了什么、为什么），范围变化必须有书面痕迹。

## 6. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| RAGAS 接千问解析失败 / NaN | D6 卡死 | D6 先 5 条冒烟再全量；锁定 RAGAS 版本；备选自写 LLM-judge 脚本 |
| 测试集质量差 | 后面所有数字不可信 | D4–D5 花两天，30% 项目时间；冻结后改动必须升版本 |
| 模型输出不稳定 | 前后对比失真 | 评测统一低温（如 temperature=0 或 0.1）；同配置跑同版本模型；D15 回归验证 |
| embedding 成本/限流 | D1 入库慢 | 批量 + 本地缓存 + 失败重试；不追求实时 |
| 范围膨胀 | 15 天变 20 天 | 第 5 节裁剪顺序 + 5.1 治理铁律；新想法只进 backlog |
| 分数未达参考值引发凑分冲动 | D7–D8 变 D7–D11 | 第 1 节参考值使用规则：未达标=记录原因即完成，实验组数封顶 |
| 人工标注（D4–D5、D9）低估个人时间消耗 | 标注质量下降、冻结延期 | 标注日不排并行任务；提前整块留出专注时间；AI 不代做人工判断 |
| 时间不足 | 核心被挤 | 核心不可砍，宁可砍 D12 下午和 D13 可选 |
