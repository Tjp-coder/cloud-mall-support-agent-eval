# KB 模拟文档模板(v1 · 2026-08-16)

> 用途:8 份模块 KB 模拟文档的统一格式,每份独立成文件,入库时按文件分块。
> 来源口径:基于在职期间的业务理解自行整理编写,数值为自洽设计(模拟文档,不追求还原真实),细节可与前后同事核对。
> 写作三律:① 事实只写一次;② 单主题、一句话可答;③ 必须含精确数值,禁止"大概/左右/估计"。

## 1. 文档结构(每份固定 6 节)

### 1.1 对象定义
本模块涉及的实体 + 编号/格式示例,是 mock 工具和越权用例的抓手。

```markdown
## 1. 对象定义
- 订单:用户购买资源的记录,订单号格式 `ORD20260816XXXX`(14 位:ORD+年月日+4位序号)
- 用户:平台注册主体,分个人/企业;企业含税号;联系方式为手机号(11 位)
- 示例对象(供用例引用):订单 ORD202608160001、用户 138****8888(企业:XX 科技有限公司)
```

### 1.2 规则条目(主体,30~45 条)

```markdown
## 2. 规则条目
### 2.1 购买与付费
- CT-101 缓冲期:容器到期未续费进入缓冲期,默认 7 天,商家端可在 1~30 天配置;缓冲期内可续费,缓冲期结束自动释放资源并停止计费。
- CT-102 三种付费:包年包月/包日下单即出账单;按量计费按小时出账,停机仍计费(占用资源),超缓冲期释放后停止计费。
- CT-103 挂载上限:单个容器最多挂载 10 个附加商品(云硬盘/文件存储/公网IP),商城下单侧限制,超出提示不可选。
### 2.2 生命周期
- CT-201 变配:支持升/降配,变更需停止容器;变配期间不产生新增费用,变配完成后按新规格计费。
- CT-202 续费:支持 1/3/6/12 个月续费;缓冲期内续费不中断服务,缓冲期外续费需先恢复资源。
### 2.3 计费与账单
- CT-301 账单周期:按量计费每小时出账一次,账单按月汇总生成月账单,次月 1 日生成。
```

**条目写法要点:**
- 每条 = `编号 + 规则名:一句完整事实(含数值、条件、例外)。`
- 条件、例外必须写清楚(这是边界用例的原料)
- 可以按小节分组(购买/生命周期/计费/附加商品…),小节名不进条目

### 1.3 状态机

```markdown
## 3. 状态机
容器生命周期:
创建中 → 运行中 → 关机中 → 已关机
   │        │ 异常→异常态        │
   └────────┴───────────────────┘
   (到期) → 缓冲期 → 缓冲期结束 → 已释放

- 创建中:提交订单后进入,创建成功→运行中,失败→创建失败(可重试)
- 已关机:停机不释放资源,按量计费继续计费
- 缓冲期:到期未续费进入,默认 7 天,可续费恢复运行中
- 已释放:缓冲期结束自动释放,停止计费,数据不可恢复
```

### 1.4 边界与拒答

```markdown
## 4. 边界与拒答
能答:购买/续费/变配/退订规则、计费规则、附加商品规则、到期处理、账单查询。
不能答(拒答依据):
- 操作类:帮我改订单/退款/注销 → 客服只能咨询,不执行操作
- 内部类:资源底层架构、价格成本构成 → 不对外
- 他域类:返佣/开票/算力券问题 → 引导对应模块(联动见第 5 节)
需澄清:
- "我的容器" 但用户有多个容器 → 要求提供订单号或实例名
```

### 1.5 联动规则

```markdown
## 5. 联动规则
- 退订 → 开票:包年包月退订按退款系数退回部分金额,若实退 < 已开票金额,触发欠票(见 IV-301)
- 到期释放 → 账单:已释放容器的按量账单计费至释放时刻,月账单含释放前费用
- 变配 → 账单:变配完成时间点作为新旧规格计费分界
```

### 1.6 闭环自检

```markdown
## 6. 闭环自检(冻结前完成)
- [ ] 抽查 10 条问题:答案均能从本文档 1~2 条推导(无"文档里没有答案"的问题)
- [ ] 无重复事实:同一规则全文只出现一次
- [ ] 边界用例原料:至少 5 条含精确数值的规则可支撑边界用例
- [ ] 状态机无悬空状态:每个状态有入口和出口
```

## 3. 虚拟机(VM)模块写法:与容器"差不多"的正确处理

VM 与容器共享的通用规则(生命周期、付费、缓冲期、变配、续费)**不重写**,用引用:

```markdown
- VM-101 通用规则:VM 的付费方式、到期缓冲期、变配/续费规则与容器一致,见 CT-101~CT-202。
- VM-102 系统盘:VM 必须配置系统盘(默认 40G,可选 40/80/160G),系统盘生命周期跟随 VM,不可单独退订。
- VM-103 镜像:支持官方镜像与自定义镜像;自定义镜像需从运行中的 VM 创建,镜像创建期间 VM 不可变配。
- VM-104 快照:支持手动快照,快照恢复将 VM 数据回滚至快照时刻;快照保留数与磁盘容量相关,上限 7 个。
- VM-105 登录方式:支持 VNC 网页控制台与 SSH 登录;VNC 无需公网 IP,SSH 需先绑定公网 IP 并配置安全组放行。
- VM-106 操作系统:支持 Linux(CentOS/Ubuntu)与 Windows;Windows 镜像默认开启远程桌面(3389)。
```

要点:每一条都是容器没有的差异点;任何一条规则若与容器相同,直接引用 CT 编号,不复制内容。

## 4. 订单与交付(OD)模块写法

订单是客服问答最高频场景,也是跨模块联动的枢纽(退订→欠票、退款→返佣冲正都从订单出发)。结构与其他模块相同,但**状态机是核心**,规则条目围绕状态展开:

```markdown
- OD-101 订单状态机:待支付 → 待审核 → 已支付 → 发货中 → 已发货 → 已完成;另有已取消/已关闭。
- OD-102 支付:支持余额支付与在线支付;支付成功后订单进入待审核(需人工审核的订单)或直接发货中。
- OD-103 人工审核:寄售订单、大额订单(单笔 ≥1 万元)需运营人工审核,审核通过后进入发货。
- OD-104 自动发货:支付/审核通过后自动触发发货,平台调用控制台开通资源,开通成功订单状态回写为已发货。
- OD-105 发货异常:开通失败时订单停留发货中并提示,不自动进入已发货。
- OD-106 取消订单:待支付订单可自行取消;已支付未发货订单取消需申请,退款原路退回或退至余额。
- OD-107 订单构成:订单金额 = 资源费 + 附加商品费 + 带宽费 − 优惠(优惠券/代金券/积分),见 RB-xxx 基数规则。
- OD-108 状态一致性:商城订单"已发货"必须对应控制台资源"运行中/创建成功",不一致视为链路缺陷(经典问题)。
```
